The backtest is the live run.

A trading bot where a backtest and a live run execute the same strategy code through the same engine loop. Only the data feed and the broker are swapped. Binance spot and USDⓈ-M perpetuals, eToro stocks and crypto, and MAX, with exact decimal money and no lookahead.

Where it trades

One engine, four venues

A venue is a provider: a market-data feed plus a broker. Adding one never touches the engine or a strategy, which is why every strategy runs on every venue that offers its asset class.

Binance spot

Testnet, Demo Trading and live. Books journaled before submit, reconciled on every start and exit. Delistings and halts handled; optional Simple Earn sweep of idle cash.

Non-negotiable

Invariants, not conventions

Each of these is enforced in the code and pinned by tests. A change that breaks one is wrong by definition.

$Money is exact

Prices, quantities, balances and fees are Decimal in unit types (Price, Qty, Notional). Config, data files and venue replies are read as text; a bare float never becomes money.

tNo lookahead

A strategy sees data only up to the current closed candle and its orders fill no earlier than the next. A test rewrites every candle after t and requires nothing up to t to change.

=Backtest equals live

One Strategy trait, one engine loop. A backtest swaps only the provider, and each venue's fill model refuses the same orders the venue would.

🔑Secrets from the environment

Keys come only from environment variables (BINANCE_API_KEY, ETORO_PRIVATE_KEY, …). No config field can hold one: api_key in a file is an unknown-field error.

3Three locks for real money

The default is paper. A real order needs mode = "live", exchange.network = "live" and --i-understand typed on the command line.

⟲Books survive restarts

Every order is journaled before it is sent and every fill recorded once by the venue's id. Start and exit reconcile with the venue, which is always the source of truth.

⏻Exits the engine enforces

Whatever the strategy does, the engine closes a coin before its delisting, and an optional kill switch closes everything once equity falls a set share from its peak. A tripped switch refuses restarts until cleared.

?Data checked, not trusted

Backtests warn about bars that jump over 30% (unadjusted splits, bad prints). On eToro the run compares its books with the account every bar and stops if a split or a manual trade changed them.

⌂A console that can't trade

trade-bot console edits script strategies and backtests them against buy-and-hold in your browser. Loopback only, no keys, no orders, and it refuses requests from other pages.

Architecture

How it works

One-way data flow. The strategy is a pure decision; the provider is the only thing that differs between a backtest and a live run.

Each event, in order

  1. The broker settles pending orders against the new event, so a decision at t fills at t+1.
  2. Fills update the strategy's position before the bar joins its history.
  3. The strategy decides; risk rounds to lot and tick (never more aggressively) and checks venue filters.

A stated fill model

  1. Market orders fill at the next candle's open, taker, with slippage you must specify.
  2. Resting limits fill only when price trades through them (on eToro, a touch: its limits execute at market).
  3. Stop and target in one candle: the model assumes the worse.
Batteries included

Built-in strategies

Quick start

Prebuilt binaries for Linux, macOS and Windows are on the releases page. Building from source needs only rustup; the toolchain is pinned. Keys always come from the environment.

~/trade-bot
# cache public history (no key needed), then backtest on it
$ make fetch-data SYMBOL=BTCUSDT FROM=2024-01-01
$ make backtest STRATEGY=buy_and_hold SYMBOL=BTCUSDT \
    FROM=2024-01-01 TO=2024-06-01 SLIPPAGE_BPS=5 PARAMS=my-params.toml
# paper trade on Binance's testnet (the default network)
$ export BINANCE_API_KEY=… BINANCE_API_SECRET=…
$ make run-paper
# USDⓈ-M: klines, funding, mark price and your margin brackets
$ cargo run -p cli -- fetch-data --venue binance-usdm --symbol BTCUSDT --from 2026-01-01
$ cargo run -p cli -- backtest --venue binance-usdm --strategy sma_long_short \
    --params p.toml --symbol BTCUSDT --from 2026-02-01 --to 2026-08-01 \
    --fee 0.0005 --slippage-bps 2 --leverage 2 --margin isolated
# eToro: data and orders need your keys (a demo user key works)
$ export ETORO_PUBLIC_KEY=… ETORO_PRIVATE_KEY=…
$ cargo run -p cli -- fetch-data --venue etoro --symbol AAPL,BTC --from 2026-01-01
# exchange.venue = "etoro", network = "demo": orders on your demo account
$ cargo run -p cli -- run --paper --config etoro.toml
